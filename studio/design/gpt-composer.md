# GPT-6 Astra 符号谱曲

## 使用方式

1. 在 `studio/.env.local` 选择谱曲服务并配置对应密钥（见下文），使用有 `gpt-6-astra` 调用权限和额度的账号。密钥只在服务端读取，不放进前端或 Git。
2. 重启 `npm run dev`，进入工作室，上传图片、填写角色故事并采用一个主题。
3. 在“场景”页选择日常／回忆／战斗，点击“生成 AI 编曲”。普通参数预览仍是本地规则生成，不会自动调用付费模型。
4. 成功后切换到 AI 编曲，仍通过现有四轨音源试听、混音、导出 MIDI 和 WAV。可以切回规则草稿。
5. AI 乐谱随工程 JSON、草稿和版本记录保存；每种场景独立保存。换主题或角色设定后，旧 AI 结果标为不匹配，继续使用规则草稿；不会把旧曲冒充成新设定的结果。

## 服务配置

公司网关：

```dotenv
AI_COMPOSER_PROVIDER=yoozoo
YOOZOO_API_KEY=你的公司网关密钥
```

官方接口（默认）：

```dotenv
AI_COMPOSER_PROVIDER=openai
OPENAI_API_KEY=你的官方密钥
```

- 公司地址固定为 `https://ai-gw-cn.uuzu.com/v1/chat/completions`，官方地址固定为 `https://api.openai.com/v1/responses`。密钥互不混用，失败不跨服务重试；切换后重启本地服务。
- 工作室显示当前谱曲服务；“检查配置”只检查是否设置密钥，不代表账户权限或余额已验证。
- 公司请求以 `image_url` 发送参考图，故事与主题放在文本消息中；以 `response_format.json_schema` 请求乐谱。拒绝、截断、无效音符不会替换作品。
- 本配置仅控制 AI 谱曲；上传后的独立高级识图接口仍使用原来的 `OPENAI_API_KEY`，没有官方额度时保留本地分析。谱曲请求本身仍可通过公司网关结合图片与故事。
- 新乐谱记录服务来源，兼容没有来源字段的旧工程。密钥不进入工程文件。
- 已用当前公司账号实测 GPT-6 Astra 的文本／故事谱曲与严格 JSON Schema，得到完整四轨乐谱并成功渲染；图片输入的请求格式已模拟验证，真实图片谱曲仍待实测。其他账号的权限与额度以各自配置为准。

## 生成内容

- 固定模型：`gpt-6-astra`；官方使用 Responses API，公司网关使用 Chat Completions API；都请求严格 JSON Schema，不执行模型返回的代码。
- 模型接收角色故事、音乐参数、可选参考图和已采用的四小节主题。
- 输出十六小节、4/4、四轨乐谱：旋律、和弦、贝斯、鼓；四个段落从第 1、5、9、13 小节开始。
- 目标为引子、主题呈现、变化／高潮、收尾。四个段落完全机械重复会被拒绝。
- 最终声音由现有采样音源／合成器渲染；这不是模型直接生成的音频，更不保证完整商业制作效果。

## 编曲清晰度调整

- 根据首轮“整体太乱”的试听反馈，默认提示改为单一短动机、单声部主旋律、较窄音域和两小节句尾留白。
- 和声改为稳定循环的两到三音持续和弦，贝斯只支撑和弦根音；允许伴奏重复，用旋律收尾与力度发展段落。
- 日常／回忆减少鼓点，开头和结尾留空；降低合成鼓力度，避免压过采样旋律。战斗仍保留稳定节拍，但避免多个声部同时演奏复杂节奏。
- 这些是生成指导，不是保证审美质量的硬性校验。已有工程不会自动改写，新生成的结果仍需试听判断。
- 同故事与主题的真实对照样例从 225 个音符降至 100 个，鼓点从 68 降至 8，旋律音域从 23 个半音收至 8 个半音。`releases/ai-company-clear*` 保存新样例；`*-preview.wav` 是统一平均电平的试听副本，仅改变整体增益，网页渲染与原始 WAV 未做该增益处理。

## 乐器选择

- “调整与导出 → 旋律音色”提供钢琴、钟琴、木吉他、弦乐铺底、长笛、小提琴、马林巴七种选择。切换已有乐谱的音色只在本地重新渲染，不调用 AI、不增加音符。
- 新增三种独立乐器采样，以及采样加载失败时的合成备用音色；长笛／小提琴有较柔和的起音，马林巴保留敲击衰减。
- 仍保留旋律／和弦／贝斯／鼓四轨。AI 提示要求互补搭配：管弦主奏配轻钢琴或弦乐底，敲击主奏配持续和声，避免多个声部同时抢主旋律。长笛／小提琴限主奏，马林巴也可作为轻和声。
- 旧工程兼容；新增音色可保存并导出 MIDI。钢琴、钟琴、木吉他的 MIDI 音色编号也已与网页采样对应，实际听感仍取决于 MIDI 播放器的音源。
- 三种音色使用同一份《沿途拾光》乐谱完成浏览器渲染与 WAV 导出；没有为此重新调用模型。试听副本仍只做整体增益调整。

## 行为和边界

- 调用前校验输入；返回后校验音符范围、长度、力度、轨道顺序、鼓映射、重复音符、段落结构和当前请求一致性。
- 手动触发，每次请求最多 18,000 输出 token；服务端超时 180 秒。无自动重试，避免失败后重复计费。
- 同一个运行实例同时仅处理一个谱曲请求。此并发保护不是面向公网多实例服务的完整用户配额系统。
- 可以取消；取消或失败保留现有作品。切换角色／主题／场景会丢弃过期结果。取消不表示服务商一定退还已经产生的费用。
- 缺少密钥、模型权限、额度或服务错误会显示明确错误，不把规则曲伪装成 AI 结果。
- 再生成已有 AI 乐谱前保留版本；达到版本数量或工程大小上限时不覆盖当前数据。
- 本次修复缺少总音量偏好时误设为 0、候选试听被编曲静音状态覆盖的问题，并将音源下载等待限制为 8 秒，随后回退合成音源。

## 验证

- 单元测试使用明确标记的模拟 provider：覆盖合法与畸形乐谱、缺少密钥、权限错误处理路径、拒绝／不完整结果、并发请求、取消，以及工程往返和 MIDI 输出。
- `releases/ai-ui-fixture.json` 为明确标注的界面模拟样本，不是实际模型创作，且被 Git 忽略。
- 真正的编曲听感、主题延续程度和生成耗时需要在 API Key 配置完成后实测，不以模拟结果替代。
- 2026-09-17 公司接口真实谱曲约 107 秒，16 小节、225 个音符；真实工程导入、播放及 MIDI／WAV 导出通过，WAV 约 40.2 秒。试听样例位于被 Git 忽略的 `releases/ai-company-real*`，听感由用户进一步评价。
